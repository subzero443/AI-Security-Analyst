# Signal Security Analyst

A local React dashboard with a FastAPI passive web-configuration scanner and a deterministic, evidence-based analysis engine.

## Run locally

Requirements: Node.js 20.19+ and Python 3.12+.

In PowerShell, install the frontend and API dependencies:

```powershell
npm install
py -3.12 -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
```

Start the API in one terminal:

```powershell
npm run api
```

Keep this terminal running while using live scans. This starts the passive scanner API at `http://127.0.0.1:8001`; scans will fail if the API is stopped.

Start Vite in a second terminal:

```powershell
npm run dev
```

Open <http://127.0.0.1:5173/>. Vite proxies `/api` requests to the API at `127.0.0.1:8001`.

The scan dialog accepts a URL or a JSON object for one website, for example `{"target":"https://your-authorized-site.com"}`. A one-item `targets` array is also accepted. Multi-target JSON is intentionally rejected; each website requires its own authorization confirmation and scan.

Optional model-assisted analysis uses an OpenAI-compatible Chat Completions endpoint. Configure the provider in the API terminal before starting `npm run api`; the credential remains on the API process and is never sent to the browser:

```powershell
$env:OPENAI_API_KEY = "your-provider-key"
$env:OPENAI_MODEL = "gpt-4o-mini"
# Optional for a compatible provider other than the default API:
$env:OPENAI_BASE_URL = "https://your-provider.example/v1"
npm run api
```

Each scan requires a separate checkbox before finding evidence is sent to the configured model. Only finding IDs, descriptions, impact, recommendations, and short evidence strings are sent; captured response bodies and cookie values are excluded. With no provider key, local deterministic analysis runs automatically. Provider failure falls back to local rules and is shown in the analysis view.

## Scan scope

Only scan websites you own or are explicitly authorized to assess. The consent checkbox is a self-attestation, not proof of authorization.

The scanner performs at most eight unauthenticated HTTP GET requests to the origin root, `robots.txt`, and `security.txt` locations. It also makes TCP connect checks to ports 80 and 443 on the first validated public IP. The report includes validated DNS addresses, web-port reachability, response headers, redirects, cookie flags, and public technology metadata. Database products are shown only if a response header or HTML generator field explicitly names one; the scanner never probes database or admin ports.

Targets must resolve only to public IP addresses. DNS answers are validated and pinned for the scan, redirects remain on the authorized hostname, responses have time/body limits, and each scan is capped at eight GET requests plus two TCP checks. Only standard web ports are tested; this is not an Nmap scan or a vulnerability-exploitation engine. The API binds to localhost by default.

Findings and prioritization are generated by local deterministic rules from observed response evidence. An optional OpenAI-compatible model can explain only the existing findings after a separate per-scan opt-in. Confidence describes evidence-to-rule fit, not exploitability. A clean result is not proof that a site is secure; the scanner does not inspect authenticated pages, application source, or business context.
